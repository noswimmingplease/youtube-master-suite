# Technical reference

Implementation, diagnostics and maintenance notes for YouTube Master Suite.
For installation and everyday use, see the [README](../README.md#installation).

## Source layout

| Path | Purpose |
| --- | --- |
| `sources/modules/` | Canonical feature-module userscripts. |
| `sources/` | Shared preference, filter, backup and support infrastructure. |
| `sources.lock.json` | Reviewed module versions and SHA-256 hashes. |
| `build-master.mjs` | Generates the installable script and release manifest. |
| `refresh-source-lock.mjs` | Validates and refreshes the canonical module lock. |
| `verify-master.mjs` | Checks build integrity, invariants and behavioural tests. |
| `verify-installed-master.mjs` | Checks exported or installed source against the manifest. |
| `youtube-master-suite.user.js` | Generated installation artefact; do not maintain it directly. |
| `release-manifest.json` | Generated version, hash, lengths and module count. |
| `assets/` | Embedded logos, settings styles and artwork notices. |
| `tests/` | Unit tests and isolated browser fixtures. |
| `examples/settings-preview.html` | Design reference, not the functional settings panel. |

The eight modules are Comment Cleaner, Feed UI Cleaner, Miniplayer Button
Restorer, Page Coherence Guard, Player Preferences Lite, Scroll Miniplayer,
Watch Layout Cleaner and Suite Settings. The [source lock](../sources.lock.json)
is the version inventory; former standalone repositories are superseded.

`youtube-master-suite.txt` is an ignored local manual-install copy. The published
artefact is the `.user.js` file.

## Build and verify

Run all commands below **from the repository root**. A normal build needs Node.js
and the committed sources; browser-test dependencies are not required.

```powershell
node .\build-master.mjs
node .\verify-master.mjs
node .\verify-installed-master.mjs .\youtube-master-suite.user.js
```

For a read-only generated-file check:

```powershell
node .\build-master.mjs --check
```

The build, lock refresher and both verifiers also support `--self-test`. Identical
locked inputs produce identical generated bytes and hashes. The build rejects
missing, orphaned, duplicated or altered unlocked module sources.

### Changing a feature

1. Edit its canonical source, not the generated script.
2. Increase the changed module's metadata version and the master version in
   `build-master.mjs` for a runtime release.
3. Refresh the lock, review its diff, then rebuild and verify:

   ```powershell
   node .\refresh-source-lock.mjs
   node .\build-master.mjs
   Copy-Item .\youtube-master-suite.user.js .\youtube-master-suite.txt -Force
   node .\verify-master.mjs
   ```

The refresher validates every module before writing. A changed module must have
a higher dotted numeric version. Documentation-only changes do not require a
script version increase or reinstall.

## Browser regression tests

Install the pinned development dependency and its matching Firefox build:

```powershell
npm ci --ignore-scripts
npx --no-install playwright install firefox
npm run test:browser
```

Tests run the complete generated script in headless Firefox, using fresh
disposable contexts and intercepted YouTube-shaped fixtures. They exercise real
browser DOM, keyboard, mouse, clipboard, layout and fullscreen APIs against
locally supplied YouTube player/page contracts. Missing browsers or unsupported
contracts fail checks rather than silently skipping them.

These tests do not connect to the user's signed-in session or running YouTube
app. They verify fixture behaviour, not Tampermonkey permissions, every live
YouTube experiment or long-session memory stability.

On Windows, explicitly target an installed browser when required:

```powershell
$env:YT_SUITE_TEST_BROWSER = "chrome"
npm run test:browser
Remove-Item Env:YT_SUITE_TEST_BROWSER
```

Supported selectors are `chrome`, `edge`, `installed-firefox` and `zen`. Unset
the variable for the default patched Firefox. The helper validates the browser's
product metadata and uses a fresh headless profile, never an existing session.
Installed Firefox and Zen use WebDriver BiDi.

For retained test profiles, the optional `YT_SUITE_TEST_ROOT` must be an existing
absolute local directory whose final component matches the selected browser.
Reparse-point ancestors are rejected. Each launch creates unique
`profile-<UUID>` and `artifacts-<UUID>` children and leaves them for inspection.
Confirm the test browser has exited before removing only its exact owned paths.

## Runtime design and safeguards

- Modules keep isolated state and failure handling while sharing one native
  mutation observer, lifecycle subscriptions and ordered stylesheet.
- Mutation work is filtered and coalesced. Label and snapshot reuse is limited
  to the relevant pass; it is not a persistent cache of recycled YouTube nodes.
- Route-specific observers stop when their feature is inactive. Navigation,
  suspension and detached elements release pending work and temporary handlers.
- Settings are created lazily with native DOM operations, compatible with
  Trusted Types. They do not require a separate polling loop.
- Unknown native contracts are left untouched rather than guessed. This limits
  damage from layout changes; it is not immunity from future YouTube changes.

### Queue and menu actions

Play next uses YouTube's native menu, add command and reorder handler. It checks
the current video, queue identity, ordered items and row bindings before adding.
A collapsed miniplayer queue can be expanded through its native header, with a
bounded two-second readiness wait. A known but unverifiable queue is not treated
as permission to append.

Each native command is sent once. Add/reorder waits are bounded to eight seconds
and cancelled if navigation, playback identity or queue identity changes. The
menu closes on selection, including preflight failure. After an accepted add,
failure can leave the video at the end; the status message must distinguish this
from a rejected operation. Ambiguous results are not automatically retried.

Stale playing-marker repairs require agreement between the active player,
temporary queue ID, current index and row bindings. They do not change playback,
queue order or saved playlists. Incomplete panels and active drags are ignored.

Queue drag assistance adjusts native edge scrolling to visible bounds and
animates inner row contents only. It preserves native drop targets, row geometry
and ordering, respects reduced motion and releases temporary resources when the
gesture ends or its context is lost.

### Channel filters

Rules use canonical channel identity and publication metadata already present
on supported cards. Conflicting IDs and uncertain dates fail open for age-only
rules. There is no per-thumbnail lookup, video download or channel-name matching.
Whole-channel rules intentionally include undated and live/upcoming cards.

Rules apply only to supported feed/search/channel surfaces. History, queues,
saved playlists and directly opened playback remain untouched. Profile-local
changes synchronise between open windows; concurrent saves do not overwrite an
edited draft silently. YouTube recommendation feedback remains separate.

### Playback, layout and extension boundaries

- Mirroring affects only the current video, not captions or controls, and resets
  on navigation. `H` works with player focus; text entry and browser shortcuts
  are not captured.
- Preferred quality is an initial request, not a permanent lock. Attempts are
  bounded and stop when the user interacts with native quality settings.
- Ordinary wheel events do not trigger volume work unless the configured gesture
  is active. Context-menu suppression is one-shot and time-bounded.
- Fullscreen-comment scrolling applies to document-root fullscreen, not browser
  F11 or isolated player-only fullscreen. Floating-player restoration waits
  while its player or video owns fullscreen.
- Fullscreen-strip hiding is off by default and targets its dedicated wrapper,
  not the main playback bar. Native quick-action artwork is excluded from the
  Suite's dislike-icon fallback.
- Clean **Copy video URL** handling uses the freshly generated native URL and
  recognised English label. Timestamp copying and unsupported labels retain
  native behaviour; there is no clipboard monitoring.
- The watch layout reserves a 374px queue rail for SponsorBlock compatibility;
  it does not control SponsorBlock. DeArrow icon visibility is separate from
  title/thumbnail replacement. External cosmetic filters can override visibility.
- Cookie handling makes at most one attempt within ten seconds, using a visible,
  recognised **Reject all** action. It never accepts optional cookies, fabricates
  consent or resets an existing preference. Unknown layouts remain manual.

## Diagnostics and fault isolation

Prefer **Settings → Support → Copy report** when reporting a fault. It produces
an allowlisted report without raw error messages, stacks, timestamps, page URLs,
video/channel IDs, titles, searches, account data or performance traces.

For local investigation, these read-only expressions expose the current state:

```javascript
JSON.parse(document.documentElement.getAttribute("data-yt-master-suite"))
JSON.parse(document.documentElement.getAttribute("data-yt-master-runtime-errors"))
JSON.parse(document.documentElement.getAttribute("data-yt-master-state"))
JSON.parse(document.documentElement.getAttribute("data-yt-master-events"))
```

The startup marker reports version, module registration/initialisation and
`ready` / `healthy`. It does not prove every feature works or include failures
raised later. Runtime errors are kept separately, bounded to the latest 20;
their shortened messages may contain contextual information, so do not share
raw diagnostics without reviewing them. Missing attributes parse as `null`.

Page coherence retains up to 20 navigation events and exposes
`__YT_MASTER_STATE__.snapshot()`, `.events()` and `.check()` when available.
Use `.snapshot()` and `.events()` for passive inspection; `.check()` actively
evaluates the recovery safeguards. Page coherence uses bounded identity checks
and, where positively justified, one native
page-data recovery attempt per navigation. Comment freshness recovery has an
eight-second deadline so uncertain recycled content cannot leave it blank
indefinitely. Replacement titles alone do not trigger recovery.

`DIAGNOSTICS` is disabled by default in the build configuration. Temporary
diagnostic builds expose `__YT_MASTER_DIAGNOSTICS__.snapshot()`, `.report()` and
`.clear()`, plus `data-yt-master-diagnostics`. Timing diagnostics are distinct
from the privacy-limited support report; disable them after investigating.

For module-level isolation, save a separate diagnostic copy of the generated
script and set only the relevant `ENABLED_MODULES` entry to `false` in that copy.
Rebuilding overwrites generated edits. Keep the diagnostic copy unpublished and
do not treat it as a permanent source change or verified release artefact.

## Backup validation

Backups contain saved preferences and the complete channel-filter list, including
channel names/IDs, but not unsaved drafts or browsing history. They stay local
unless the user chooses to share the file.

Restore requires a validated preview and confirmation, replaces rather than
merges, and rejects oversized files (over 128 KiB) and invalid schema values.
Older supported backups receive defaults for newer optional preferences.
Concurrent changes invalidate the preview. Partial writes attempt rollback and
report incomplete recovery. Filters apply immediately; other preferences need
reload. Restore does not reload automatically.

## Connected-editor workflow

TampermonkeyFS / Tampermonkey Editors is optional. Link the Suite's virtual editor
to the repository's generated `youtube-master-suite.user.js`, then:

1. Change canonical sources, refresh the lock, rebuild and verify.
2. Load the linked generated file into the virtual editor and save it to send
   the source to Tampermonkey.
3. Read the installed source back and compare it with the local artefact before
   claiming installation succeeded. Replacing source does not update a running
   page until it reloads.

Tampermonkey Editors can append a separate `---` / `Last modified: <ISO timestamp>`
synchronisation footer. Validate that footer independently and require the
canonical prefix to match exactly. For an exported/file-backed installed copy:

```powershell
node .\verify-installed-master.mjs <installed-source-path>
```

Do not refresh playback or change saved settings as part of installation without
the user's agreement.

## Release checklist

1. Review canonical changes, versions, source locks and the generated diff.
2. Run build checks, verifier/self-tests and browser tests. Check relevant live
   YouTube behaviour separately, with permission before app-affecting actions.
3. Check affected routes, recycled cards, menu keyboard/pointer behaviour, queue
   navigation, comments, miniplayers, fullscreen, live videos and extension layout.
4. If installing, verify source readback against `release-manifest.json`.
5. Commit and push; require successful CI for that exact commit.
6. Run the release verifier, then tag and publish the verified artefacts:

   ```powershell
   node .\verify-master.mjs --release --base HEAD^
   ```

Release mode requires clean `main` tracking and exactly matching `origin/main`,
a version newer than other stable tags, correct placement of the current-version
tag if present, and a matching local `.txt` copy. Use the appropriate comparison
base if the release spans more than one commit.

CI runs build integrity, safeguard self-tests, behavioural tests, separate
Firefox regression checks, JavaScript syntax checks and a clean-build check.
Release-tag pushes do not repeat the already-tested `main` run.

Publishing does not update installed scripts: `@updateURL` and `@downloadURL`
are `none`. Never put authentication tokens in userscript metadata.
